# 数据分析 Agent

基于 Code-as-Action 的数据分析 agent：模型只生成 pandas 代码，代码在隔离子进程中执行，
数据本身不进入上下文，所有数值均来自实际执行结果。

配套一套可复现的评测：42 道题、6 个版本、版本指纹与逐题轨迹，用于判断每次改动是否真的有效。

---

## 背景

让模型直接读取表格并计算存在两个问题：

1. **容量**：数据量大时无法放入上下文。在 21 道题的早期评测集中，有 7 道题的数据最多只能显示 2.4%。
2. **可靠性**：即使表格只有 32–60 行，模型仅凭阅读也会算错，且错误结果看起来正常。

本项目采用的做法是让模型生成代码、由 Python 解释器执行，只把 stdout 与 traceback 回传模型，
从而把"读表计算"转换为"写程序"，并让数值有可核对的来源。

```
用户提问 → 模型生成代码 → 子进程执行 → 回传 stdout / traceback
              ↑                              │
              └──────── 有错则修改，最多 10 步 ┘
```

---

## 设计取舍

### 1. 数据不进上下文，只进画像

`load_data` 返回列名、类型、缺失数、唯一值数、前 5 行与数值概要，不返回全量数据。
模型通过 `dfs['数据集名']` 在代码中访问 DataFrame。

### 2. 工具的返回值承担领域约定

`load_data` 在返回画像时会检测并报告数据问题，包括：

- 编码异常的数值列（通过"删除数字后剩余的字符"统计，能自动发现单位后缀、小数逗号等，不依赖预置规则）
- 疑似汇总行（单位代码列中的空值或非标准格式行、分类列中的"合计/total"取值）
- 列名首尾空白与不可见字符（这一项在数据入口直接修复，不再提示模型）
- 文本列中可转换为数值的比例

数据质量提示将早期评测集上 3 道口径题的通过率从 67% 提升到 100%，token 下降 22%。

### 3. 修正在入口完成，判断交给模型

列名规范化在 `_normalize_df()` 中完成，属于无歧义的修正。
去重、缺失填充、剔除汇总行等依赖问题口径的处理不由代码代做，只报告事实。

实测反例：将"有 N 行完全重复"写入提示后，模型会执行未被要求去重，
使"真实记录数"类题目由 150 变为 147。该提示已移除。

## 实验记录

每个改动均跑对照实验。以下四项有完整数据：

| 改动 | 结果 | 证据 |
|---|---|---|
| 数据入口报告异常行 | 有效 | 3 道口径题通过率 67% → 100%，token −22% |
| 自动规范化列名 | 有效 | 脏数据题报错步 1 → 0，步数稳定为 4 |
| 历史消息压缩 | **负收益，默认关闭** | token +7%，缓存命中率 93% → 72% |
| 提示"有 N 行重复" | **负收益，已移除** | 诱导模型执行未被要求的去重 |

历史压缩为负收益的原因：

- 单条工具输出仅数百字符，压缩节省不足 1k token；信息丢失后模型需要多走一步，而单步需重发全部历史，约 3,900 token。
- 压缩修改历史中段内容，破坏 prompt 前缀缓存。

需要说明的是，该结论针对"每轮无条件逐条截断"这一实现，而非压缩方法本身：
按 token 压力触发、将较早轮次压缩为单条摘要、原文保留在会话日志中的实现方式不在此结论范围内。

v4 之后新增两版题型：v5 增加 6 道多轮追问（含 5 轮长对话），v6 增加 3 道方法选择题
（混杂因素、偏态下的集中趋势、检验前提）。v6 三题当前全部通过，未发现改进空间。

## 基线对比

同一套 21 道题：

| 方案 | 通过率 | 平均 token |
|---|---|---|
| 将 CSV 放入 prompt，由模型直接阅读 | 57.1%（12/21） | 4,367 |
| 本项目 | 95.2%（20/21） | 8,096 |

适用边界：以上数据仅与"直接把数据放入上下文"这一最简方案对比，**不与 ChatGPT、Claude
等产品的代码解释器做过严格对比**，因此不构成对其性能优劣的结论。

## 评测方法

```
eval_task/
├── v1/  10 题  100.0%
├── v2/  16 题  100.0%
├── v3/  21 题   95.2%   ← 朴素基线所在版本
├── v4/  33 题   90.9%
├── v5/  39 题（+6 道多轮追问）
└── v6/  42 题（+3 道方法选择题）
```

标准答案由 `scripts/gen_tasks.py` 用 pandas / scipy 现算，不手工填写。
手写标准答案会引入错误，而标准答案一旦错误，后续所有结论均不成立。

每次运行记录：版本号、题目指纹（题目文件 sha256 前 8 位）、代码 commit、
逐题通过情况、步数、token、缓存命中率、工具调用轨迹。

```bash
python -m evals.run_eval --set v6              # 全量评测
python -m evals.run_eval --set v6 --ids a,b    # 指定题目
python -m evals.run_eval --set v6 --repeat 3   # 重复 3 次取中位数
python -m evals.compare                        # 与上一次运行对比，列出修复与回归
python -m evals.show_trace --set v6            # 生成 HTML，查看每一步执行的代码
```

单次评测的 token 波动可达 ±26%（模型有时 3 步完成、有时 7 步），因此对照实验至少重复 3 次取中位数。

## 实现中的几个问题

1. **判据错误会伪装成模型失败**。曾两次将正确答案判错：一次是千分位分隔符（`36,193` 与 `36193`），
   一次是 Unicode 减号（`−0.7762` 与 `-0.7762`）。现规定：出现失败先核对判据与答案原文。

2. **同一问题存在两种口径**。某销售数据中"华东区订单记录 9 条"，但金额字段有 1 个缺失，
   按金额非空计数得 8。此类题目的标准答案必须在题面中明确口径。

3. **运行环境限制需要写进出题规范**。沙箱仅安装 pandas / numpy / scipy，没有 statsmodels，
   因此两因素方差分析一类题目无法完成。

## 已知限制

| 限制 | 说明 |
|---|---|
| 数据规模 | 单表 10 万行以内，全量载入内存，不做分块或查询下推 |
| 适用范围 | 不生成 SQL、不接入多数据源、不做多表建模 |
| 依赖库 | 沙箱仅含 pandas / numpy / scipy / matplotlib，无 statsmodels |
| 评测集 | 42 道题覆盖已知失败模式，存在未覆盖的盲区 |
| 用户验证 | 目前仅个人使用，未收集真实用户反馈 |
| 历史压缩 | 默认关闭，原因见实验记录 |

## 数据来源

`eval_data/` 下 23 个数据集均来自公开渠道（ECB、世界银行、OWID、UCI、R datasets），
各自的许可证与原始地址记录在每个数据集目录的 `meta.json` 中（字段 `license` / `source` / `url`）。
本项目仅用于评测，不主张对这些数据集的任何权利。
