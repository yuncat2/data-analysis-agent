# v1 — 首个可用基线（2026-11-04）

## 这一版是什么

10 道题，覆盖三类场景：

| 类别 | 题数 | 内容 |
|---|---|---|
| 脏数据鲁棒性 | 5 | 鸢尾花干净版 + 4 级脏数据（单位后缀 / 小数逗号+缺失 / 合计行+列名空格 / GBK 编码） |
| 合计行识别 | 1 | `heavy_rows`：问"有多少条真实记录"，原始文件 151 行（含 1 行汇总） |
| 聚合计算 | 3 | `sample.csv` 的 region / product / 总额聚合 |
| 多数据集 | 1 | 同时加载鸢尾花和 sample，各报行数 |

## 判定规则（这一版是怎么判的）

- 从回答里抽出所有数字，要求 `expect_numbers` 里每个数字都能在 `tol` 容差内找到
- **必须先去千分位逗号**：`36,193` 要先变成 `36193`，否则会抽成 36 和 193
  （第一版漏了这个，导致 3 道题假阴性，通过率被误报成 70%）

## 基线结果

| 指标 | 数值 |
|---|---|
| 通过率 | 10/10 = 100% |
| 平均步数 | 4.1 |
| 平均 token | 8,381 |
| 平均耗时 | 11.3s |

## 已知问题（这就是 v2 要解决的）

1. **太简单了，100% 没有区分度** —— 改任何东西都测不出来
2. **缺"不可能完成"的题** —— 没测过它会不会编数字
3. **全是单轮** —— 项目支持多轮，但评测还没覆盖追问和指代
4. **没有真实业务数据** —— 全是 iris / 玩具级 sales，没有长表、时间序列、多表

## 下一步（v2 方向）

- 加"数据不足时该说不知道"的题
- 加多轮追问题
- 加难度分层（easy / medium / hard）
- 目标：通过率压到 50–70%，保留进步空间
