# v5 — 多轮追问 + 两项上下文实验（2026-11-12）

## 这一版是什么

v4 的 33 道 **+ 6 道多轮题** = 39 道。

多轮题用 `turns` 字段描述，判据只看最后一轮：

| 题目 | 轮数 | 考什么 |
|---|---|---|
| `mt_iris_01` | 2 | 指代：「那 setosa」依赖上一轮的品种集合 |
| `mt_sales_01` | 2 | 口径陷阱：华东 9 条记录，但 amount 有 1 个缺失，按金额计数会得 8 |
| `mt_mtcars_01` | 2 | 指代：「那 8 缸」延续上一轮的分组维度 |
| `mt_ecb_01` | 2 | 第二轮复用第一轮的时间筛选 |
| `mt_multi_01` | 2 | 多数据集：「行数较少的那个」需要定向 |
| `mt_long_01` | **5** | 长对话，专门用来触发历史压缩并检验它是否损害指代 |

新增工具：`--multi`（只跑多轮）、`--ids`（跑指定几道）、`--repeat N`（整轮重复取中位数）。

多轮题结果：**6/6 = 100%**，指代全部解对。

## 实验一：历史压缩 → **负收益，默认关闭**

对象：`mt_long_01`（5 轮），各跑 2 次。

| 组 | 步数 | token | 缓存命中 |
|---|---|---|---|
| 关闭压缩 | 11 | 35,508 / 36,312 | 93% |
| 激进压缩（KEEP=2, TO=200） | 11–12 | 39,427 / 37,489 | 70–74% |

**为什么亏（两个原因）**：

1. 单条工具输出只有几百字符，压下来省不到 1k token；但信息丢失让模型多走一步，而**多一步要重发整个历史 ≈ 3,900 token**。
2. 压缩改变了历史中段内容 → **破坏 prompt 前缀缓存**，命中率 93% → 72%。

**结论必须收窄**：亏的是「每轮无条件、逐条截断」这个**实现**，不是压缩这个方法本身。成熟实现（如 DSH 的 `compaction`）做的是另一件事：

- 由 token 计量**按压力触发**，压力不够时一个字都不动
- 把较早的多轮压成**一条摘要**（结构真的变小）
- 被压掉的原文仍留在 session log，可回放
- 超大工具输出走 spill（存盘 + 上下文只留定位符）

代码保留能力，默认关闭：`$env:AGENT_COMPRESS = "1"` 可开。

## 实验二：数据质量提示 → **正收益，默认开启**

**动机**：v4 里 3 道错题（`le_rank_implicit` / `gdp_rank_implicit` / `gdp_median_2020`）的根因都是同一个——数据里混着收入分组、地区、OWID 区域码等汇总行，模型**不会主动检查**，直接算了。

修法不是加工具、也不是改 prompt，而是让 `load_data` 的画像**主动报告**：

```
【数据质量提示】
- iso3：像单位代码列，其中 120 行为空、0 行不是三位大写码
  → 这些通常是汇总/区域行，按「国家/单位」统计排名前应先排除
- country：出现疑似汇总行取值 ['IDA & IBRD total', 'IDA total']
```

检测 5 类迹象：列名空格 / 代码列含汇总行 / 汇总关键词 / 文本但能转数字 / 完全重复行。
**干净数据不会多一个字**（如 `sample.csv`、`iris`）。

**A/B 结果（3 道难题，各跑 2 次）**：

| 组 | 通过率 | 平均步数 | 平均 token |
|---|---|---|---|
| 提示关闭 | 4/6 = 67% | 5.5 | 13,334 |
| **提示开启** | **6/6 = 100%** | **4.85（−12%）** | **10,419（−22%）** |

**最有价值的观察**：关闭提示时它的表现是「靠运气」——第一次 3/3 全对（自己摸索用了 6.3 步），第二次 4 步就自信地算错。开启后两次都稳定 3/3。

> 提示把「有时能想到」变成了「稳定想到」。这比单纯提升通过率更有意义。

代码开关：`$env:AGENT_QUALITY_HINTS = "0"` 关闭（用于 A/B）。

## 已知局限

1. A/B 样本小（3 题 × 2 次），需要跑全量 v5 确认
2. 通过率已接近天花板（多轮 100%），要把难度压下来得靠更刁的题
3. 单次评测 token 波动可达 ±26%，**A/B 必须 ≥3 次取中位数**

## 实验三：「完全重复行」提示 → **删除**

第一版的质量提示里有第 5 条：`有 3 行完全重复（是否算独立观测取决于口径）`。

**删掉了，因为它分类错了。**

| 提示 | 不处理会怎样 | 该留吗 |
|---|---|---|
| 列名有前后空格 | `df['col']` KeyError | ✅ |
| 像单位代码列、含汇总行 | 排名/中位数算错 | ✅ |
| 文本但能转数字 | 求和变字符串拼接 | ✅ |
| **有 N 行完全重复** | **取决于问题**：问「多少条记录」要保留，问「多少条唯一观测」要去重 | ❌ |

放进【数据质量提示】区块，模型会解读成"这是待修的问题"，从而做它没被要求的去重 ——
`heavy_rows`（问真实记录数）会从 150 被打成 147。

**原则（可复用）**：提示区块只放「**不处理必错**」的迹象。取决于口径的事实，让模型自己用
`df.duplicated().sum()` 去查，不要预先塞给它。

### 验证：受影响子集（9 道 iris 相关）

删掉后 iris 不再产生任何提示（该数据集唯一触发项就是重复行）。跑两次：

```
第 1 次：9/9 = 100%   平均步数 5.3   token 12,504
第 2 次：9/9 = 100%   平均步数 5.0   token 12,152
```

无退化。

## 什么改动跑什么范围（决策框架）

| 改动性质 | 影响面 | 跑什么 |
|---|---|---|
| 改 prompt / 工具描述 / 模型 | 所有任务 | **全量** |
| 改工具返回内容 | 只在特定数据上触发 | **受影响子集** |
| 改某道题的判据 | 那道题 | 单题 |
| 改架构（如压缩） | 所有长对话 | 全量 ×3 |

**判据**：你能列出"哪些任务会受影响"吗？能 → 子集；**列不出来 → 说明不懂传播路径 → 必须全量**。

成本参考：全量 39 题 ≈ 13 分钟 / 约 0.3 元；子集 9 题 ≈ 2 分钟 / 约 0.05 元。
机器时间不占人的注意力，所以"省时间"通常不是理由——**真正的理由是"别让已知缺陷污染结果"**。

## 实验四：列名规范化（数据入口自动修）→ **正收益**

**原则（用户提的，和老师的思路一致）**：

> 人能在代码里解决的，就不要丢给模型。

但要加一个约束：**只做语义不变的修正**。

| 修正 | 自动做？ | 理由 |
|---|---|---|
| 列名去首尾空格 / 不可见字符 | ✅ | 没人会故意要带空格的列名 |
| 去重 | ❌ | 取决于「记录数 vs 唯一观测数」的口径 |
| 填缺失 / 剔汇总行 | ❌ | 同上 |
| 去单位转数字 | ❌ | 会丢掉原始文本 |

实现：`_normalize_df()` 在 `load_data` 读文件后、入库前执行。返回文本分成两段，语义明确：

```
【已自动处理，无需你干预】
- 列名已自动规范化：'sepal_length '→'sepal_length' …等 4 个

【数据质量提示】
- species：出现疑似汇总行取值 ['合计'] → 统计前应排除
```

同时**删掉了「列名有前后空格」这一条提示**——既然已经自动修好，再提示等于让模型多写一行 strip。

### 结果（5 道脏数据题，跑两次）

| | 改动前 | 改动后 |
|---|---|---|
| 通过率 | 5/5 | 5/5 |
| dirty_03 步数 | 6 / 7（两次不同） | **4 / 4** |
| dirty_03 token | 13,047 / 17,140 | 7,892 / 8,088 |
| 报错步 | 1 | **0** |

**最有价值的是「一致性」**：改动后 4 道 dirty 题每次都恰好 4 步；改动前同一道题在 6 步和 7 步之间跳。

诚实说明：样本小、方差大，不能过度解读单次 token 差异。可靠的是两个信号——**报错步归零**、**步数变稳定**。
