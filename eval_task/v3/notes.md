# v3 — 歧义口径题（2026-11-04）

## 这一版是什么

v2 的 16 道题 **+ 5 道歧义型题** = 21 道。

v2 的教训是"加数据不等于加难度"，所以 v3 换了设计思路：**难度来自口径歧义，不来自数据规模**。

| 题目 | 难点设计 | 标准答案 |
|---|---|---|
| `china_gdp_rank` | 2020 年人均 GDP 排名，数据里混 4 行收入分组（iso3 为空），不排除会得 95 | 94 |
| `china_le_rank` | 三层陷阱：全部行 68 / 只排除 Code 为空 67 / 再排除 OWID 区域码 65 | 65 |
| `ecb_peak_month` | period 是月度字符串，要先按 2022 前缀筛再取最大；输出要带月份 | 10.6 + `2022-10` |
| `gdp_total_absent` | 数据只有「人均」GDP，没有总量，正确行为是说明这一点而非编造 | 关键词 |
| `two_datasets_rank` | 同一会话里查两份数据的排名（测多数据集） | 94 + 65 |

标准答案仍由 `scripts/gen_tasks.py` 用 pandas 现算（`_gdp_china_rank` / `_le_china_rank` / `_two_ranks`）。

## 基线结果

| 指标 | v2 | v3 |
|---|---|---|
| 通过率 | 16/16 = 100% | **20/21 = 95.2%** |
| 平均步数 | 3.8 | 4.0 |
| 平均 token | 7,180 | 8,096 |
| 缓存命中率 | 83.0% | 83.0% |

## 唯一的失败及根因

`two_datasets_rank` 失败：人均 GDP 排名 **94 正确**，预期寿命排名报 **67**（正确 65，参与排名 246 个国家）。

根因：它只排除了 `Code` 为 `NaN` 的汇总行（→ 67），**没有排除 `OWID_WRL`、`OWID_EU27` 这类"有 Code 但不是三位国家码"的区域行**（→ 65）。

对比同一批里的 `china_le_rank`：**相同的数据、相同的口径，它通过了**。差别只在指令：

| 题目 | 指令写法 | 结果 |
|---|---|---|
| `china_le_rank` | 「它们的 **Code 不是三位国家代码**，需要排除后排名」 | 65 ✓ |
| `two_datasets_rank` | 「两份数据都要**排除汇总行**后再排名」 | 67 ✗ |

→ **结论：在精确指令下它做对，在模糊指令下它做不对。** 这不是随机的，是可复现的能力边界。

## 成本信号

歧义题明显更贵：

| | 常规题 | `china_gdp_rank` |
|---|---|---|
| 步数 | 3 | **8** |
| token | ~5,000 | **24,292** |

"想不清楚"会直接变成步数和成本。这个信号比通过率更早暴露问题。

## 已知问题（v4 方向）

1. **95.2% 仍偏简单**。5 道新题只压掉 4.8 个百分点，离 60–70% 还差 **8–10 道歧义题**
2. 没有格式严格题（要求 markdown 表格 / 指定小数位）
3. 没有"多轮追问"题（评测仍是单轮，而项目支持多轮）
4. 歧义题容易变成"指令遵循测试"——需要更多"指令不精确、要自己发现陷阱"的题

## v4 候选方向

| 方向 | 例子 |
|---|---|
| 不点破陷阱 | 「2020 年中国预期寿命排第几」（**不提**汇总行），看它是否自己发现 |
| 格式严格 | 「输出 markdown 表格，保留 2 位小数，按排名升序」 |
| 多轮 | 先问排名，再追问"那 2019 年呢" |
| 统计方法 | 「两种补充方式的效果有差异吗」（需要选检验方法） |

# 附：对比基线（`python -m evals.baseline_naive --set v3`）

回答面试里最尖锐的那一问：**「你的 agent 比直接把表格丢给 ChatGPT 强在哪？」**

## 实验设计

- 不装工具，把 CSV 内容直接塞进 prompt（单题上限 15,000 字符，超出截断并告知模型）
- 一次 API 调用让模型直接答，判据与 agent 完全相同

## 结果

| | agent | 朴素基线 |
|---|---|---|
| **通过率** | **20/21 = 95.2%** | **12/21 = 57.1%** |
| 平均 token | 8,096 | 4,367 |
| 平均耗时 | 9.3 s | **1.4 s** |
| 被截断的题 | 0 | **7/21** |

## 三个结论

**① 差距 38 个百分点。** agent 贵约 1.9 倍 token，但准确率高得多。

**② 大数据直接不可行。** 7 道题的数据塞不进上下文（`owid_life_expectancy` 21,565 行、
`ny_gdp_pcap_cd` 6,384 行等），朴素方案在这类题上**不是"答错"，而是"看不到数据"**。

**③ 最有说服力的一条：`toothgrowth_supp_len` 失败。**

那个文件只有 **60 行**，完全塞得进上下文，朴素基线还是算错了（要求 20.6633 / 16.9633）。

> 这就是 Code-as-Action 存在的全部理由：**数字必须来自真实执行，不能来自模型心算。**
> 数据小到能塞进去也不行——模型会"大概算一下"，然后给你一个看起来合理的错数。

这也是本项目核心设计的实证支撑，可以写进 README 和面试讲稿。
