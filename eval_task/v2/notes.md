# v2 — 引入真实数据集（2026-11-04）

## 这一版是什么

v1 的 10 道题 **+ 6 道新题** = 16 道。

新题用的是 `eval_data/` 里的真实公开数据集（7.88 MB，23 个）：

| 题目 | 数据集 | 规模 | 标准答案 | 判据 |
|---|---|---|---|---|
| `mtcars_cyl_mpg` | R mtcars | 32×12 | 26.6636 / 19.7429 / 15.1 | 数字容差 0.01 |
| `toothgrowth_supp_len` | R ToothGrowth | 60×4 | 20.6633 / 16.9633 | 数字容差 0.01 |
| `life_exp_2020_max` | OWID 预期寿命 | 21,565×4 | 86.0893 | 数字容差 0.01 |
| `ecb_hicp_2022_mean` | ECB HICP | 240×3 | 8.3583 | 数字容差 0.01 |
| `china_gdp_2020` | 世界银行人均GDP | 6,384×4 | 10627.4638 | 数字容差 1.0 |
| `absent_entity` | 世界银行人均GDP | 6,384×4 | 期望出现"没有/不存在"等 | 关键词 |

标准答案全部由 `scripts/gen_tasks.py` **用 pandas 现算**，没有手抄。

## 判定规则

在 v1 的基础上增加一类：

- `expect_numbers`：答案里必须出现这些数字（带容差）
- `expect_text_any`：答案里必须出现其中任一短语 —— 用于"数据里没有这东西，该明说没有"的题

| 指标 | v1 | v2 |
|---|---|---|
| 通过率 | 10/10 = 100% | **16/16 = 100%** |

## 结论：这 6 道新题**没有提高难度**

这是本版最重要的发现，也是一个反面教材：

> **加真实数据集 ≠ 加难度。**

原因分析：

1. **模型写代码，不读数据。** 数据集是 32 行还是 58,824 行，对它几乎没区别——它生成的是 `groupby` 和 `filter`，不是"人工翻表"。所以规模根本不构成难度。
2. **标准 groupby / 精确筛选是它最擅长的。** 这类题它一次就过，甚至比 v1 的脏数据题更快（3 步 vs 4–7 步）。
3. **`life_exp_2020_max` 本来想考"汇总行混入"**，但我问的是"最高值"——地区汇总恰好都很低，取 max 天然避开，所以没有真正考到过滤能力。**这是出题失误**。
4. 平均 token 反而下降了（7180 < 8432），说明新题比老题**更简单**。

## 已知问题（v3 要解决）

1. **仍然 100%，无区分度**
2. 难度设计思路错了：不应按"数据规模"设计，应按**任务歧义性**设计
3. 缺少需要**多步推理**的题（两个数据集 join、先判断口径再计算）
4. 缺少**输出格式严格**的题（要求特定表格结构 / 小数位）

## v3 方向（按有效性排序）

| 方向 | 例子 | 为什么难 |
|---|---|---|
| **反向问（取最低 / 排除汇总）** | "2020 年预期寿命最低的 3 个国家" | 地区汇总行会混进结果 |
| **多数据集联合** | "中国 2020 年人均 GDP 与 2020 年预期寿命，哪个排名更靠前" | 需要两次加载 + 比较 |
| **口径判断** | "2022 年通胀最高的月份" | 要理解 period 是月度、value 是同比 |
| **统计方法选择** | "两个补充方式的效果有差异吗" | 该用 t 检验还是别的，需要判断 |
| **格式严格** | "输出成 markdown 表格，保留 2 位小数" | 明确格式要求，容易不达标 |
